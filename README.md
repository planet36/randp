# AES-CTR Random Pool (randp)

AES-CTR Random Pool (also known as <q>randp</q>) is a C library, designed for modern x86-64 Linux systems, with functions that give pseudorandom numbers.  It was inspired by [arc4random](https://en.wikipedia.org/wiki/RC4#RC4-based_random_number_generators), and it mimics its functionality.

## API

The API is designed to be compatible with the arc4random family of functions.

| Description | arc4random family | randp family |
|---|---|---|
| Fill a buffer with _n_ random bytes | `void arc4random_buf(void* buf, size_t n)` | `void randp_bytes(void* buf, size_t n)` |
| Return a uniform random unsigned integer | `uint32_t arc4random()` | `uint8_t randp_u8()`<br />`uint16_t randp_u16()`<br />`uint32_t randp_u32()`<br />`uint64_t randp_u64()` |
| Return a uniform random unsigned integer less than _upper_bound_ | `uint32_t arc4random_uniform(uint32_t upper_bound)` | `uint32_t randp_lt_u32(uint32_t upper_bound)`<br />`uint64_t randp_lt_u64(uint64_t upper_bound)` |

## Design

The randp structure stores random bytes in a pool that can be retrieved later by the functions listed above.

Each thread has its own randp structure, so the functions need no locking.  The structure is `mmap`d with flags `MAP_PRIVATE | MAP_ANONYMOUS` and then `madvise`d with `MADV_DONTDUMP` and `MADV_WIPEONFORK`, and a `static` `thread_local` pointer refers to it.  Its size is at most one page (4096 B), and it's not allocated until immediately before first use.  When a thread exits, a C11 thread-specific storage destructor `munmap`s its structure.  See [src/allocate.h](src/allocate.h) for details.

Upon first use, the pseudorandom number generator (PRNG) is seeded by `getentropy`.  See [src/aes_ctr_128_prng.h](src/aes_ctr_128_prng.h), or [src/aes_ctr_256_prng.h](src/aes_ctr_256_prng.h) in a VAES build, for details.  Then the pool is filled with random bytes generated by the PRNG.

As bytes are retrieved from the pool, they are zeroized.  When the pool is depleted, the PRNG generates a fresh pool of random bytes.  After a configurable number of such refills (1024 by default), the PRNG itself is reseeded via `getentropy` before generating the next pool.  See [src/randp.c](src/randp.c) for details.

## Dependencies

### To build and use randp

* An x86-64 processor with [AES instructions](https://en.wikipedia.org/wiki/AES_instruction_set) and SSE4.1 (x86-64-v2)
* [Linux 4.14](https://kernelnewbies.org/Linux_4.14) or newer
  * [`MADV_WIPEONFORK`](https://man7.org/linux/man-pages/man2/madvise.2.html#:~:text=of%20memory%20pressure.-,MADV_WIPEONFORK) was added in Linux 4.14.
* [GCC 14](https://gcc.gnu.org/gcc-14/changes.html) or newer
  * The `-std=c23` option was added in GCC 14.  randp uses [C23](https://en.cppreference.com/w/c/23) features such as `constexpr`, `nullptr`, `typeof`, and [`thread_local`](https://en.cppreference.com/w/c/keyword/thread_local).
  * clang and clang++ are not supported.
* [Glibc 2.34](https://www.phoronix.com/news/GNU-C-Library-Glibc-2.34) or newer
  * [`getentropy`](https://man7.org/linux/man-pages/man3/getentropy.3.html) was added in glibc 2.25. [^getentropy_1] [^getentropy_2]
  * [`explicit_bzero`](https://man7.org/linux/man-pages/man3/explicit_bzero.3.html) was added in glibc 2.25.
  * [C11 threads](https://en.cppreference.com/w/c/thread) (`tss_create`, `tss_set`, `call_once`) were implemented in glibc 2.28, but lived only in `libpthread`. [^threads_1]  randp doesn't link with `-lpthread`, so it needs glibc 2.34, where `libpthread` was merged into `libc`. [^threads_2]

## Build

The version comes from the latest git tag, so a build outside a tagged git checkout needs `VERSION=X.Y` passed to `make`.

* `make`
  * Build the libraries, the header-only file, the pkg-config file, the tests, and the benchmarks.
  * The tests and benchmarks have their own dependencies.
* `make install`
  * Build and install only the libraries, the headers, and the pkg-config file.
  * `PREFIX` (default `/usr/local`) and `DESTDIR` set where they go.

Link with `-lrandp`, or get the flags from `pkg-config --cflags --libs randp`.

## Header-only

Run `make randp-single.h` to generate a [header-only](https://en.wikipedia.org/wiki/Header-only) file of randp.  It defines every function as `static`, so each translation unit that includes it gets its own copy of the code and its own per-thread pool, seeded separately.

## FAQ

### Is randp a cryptographically secure pseudorandom number generator ([CSPRNG](https://en.wikipedia.org/wiki/Cryptographically_secure_pseudorandom_number_generator))?

No claims are made that randp is a CSPRNG, but the random numbers it produces are practically unpredictable (i.e., computationally infeasible to predict).  It is built on AES, and it is seeded and periodically reseeded by `getentropy`.  It lacks three things a CSPRNG claim needs: a formal security proof, independent review by third parties, and compliance with a standard such as [NIST SP 800-90A](https://csrc.nist.gov/pubs/sp/800/90/a/r1/final).
